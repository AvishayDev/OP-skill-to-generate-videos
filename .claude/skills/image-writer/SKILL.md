# Image Writer — paint every pixel

The engine is a loop over every pixel. You decide each pixel's color with math — your own reasoning, written as a
formula — and it is written with `ImageWriter.writePixel`, then saved as a PNG. For a film you paint frame after
frame with `t` moving, and ffmpeg joins the frames into an mp4. Nothing is downloaded or generated by AI, so it
always works where Java and ffmpeg do (both are preinstalled here).

## Pixel-only — the one law of this skill
**The only way a color reaches the image is `pixel(x, y, t)` → `ImageWriter.writePixel`.** Nothing else:
- **No camera, no scene, no geometry primitives** (Sphere, Plane, Triangle, Polygon…), no rays, no light objects,
  no materials. This is not the Mini-Pro ray tracer — only its ImageWriter. A planet is a circle's signed
  distance plus shading math you write; "3D" is a formula (a normal from `sqrt(1 - r²)`, a perspective divide).
- **No drawing APIs**: no `Graphics`/`Graphics2D`, `fillRect`, `drawString`, `drawImage`, `java.awt.geom` shapes,
  `BufferedImage`, `ImageIO`, Swing/JavaFX/Canvas, and no other program or engine making frames.
- **Text** is a `Lettering`: the font file is read only for its letter outlines, which become a signed distance
  — in `pixel()` you fill it (`coverage(d)`), glow it (`exp(-d / size)`), outline it (`abs(d) - k`) yourself.
- **Pictures** (a logo, a photo) are a `Picture`: its pixels are sampled inside `pixel()` with `over(…)`.
- **Shapes** are distances from `Paint`: `circle`, `roundBox`, `segment`, or your own.

`paint.sh` enforces it: it runs `check.sh` on the painting first and refuses any camera, scene, primitive, light,
drawing call or other renderer (comments and strings don't count). `npm test` checks the kit and the examples.

```
.claude/skills/image-writer/paint.sh <Painting.java> <OUT> [options]
  OUT  still.png             one image (at --at seconds, default 0)
       name-grid.jpg         6 frames spread over the film on one sheet: Read it before the long render
       film.mp4              every frame, then ffmpeg (H.264, yuv420p, silent); a rerun continues an interrupted film
       some/dir              the PNG frame sequence only
  --size 1080x1920  --seconds 6  --fps 30  --at 2.5  --aa 2 (2×2 samples per pixel)  --set key=value (repeatable)
```
Speed: about **0.5 s per 1080×1920 frame** on 4 CPUs for a rich painting (a 6 s film at 30 fps ≈ 1.5 min, one minute
≈ 15 min). `--aa 2` costs 4×; use it for stills, rarely for films. Long films: Bash `run_in_background`.

## When to use it
1. **Fallback, always available.** An image, element or shot is needed and the usual tool can't make it: no
   `PEXELS/PIXABAY` key or the host is blocked, the search found nothing usable, a library skill fails to install,
   reelkit/canvas can't run, or making it would need paid AI and the user hasn't allowed that. Paint it instead,
   and say so in one line ("no stock photo of X, so I painted it").
2. **The user asks for an image or a video and we have no tool for it.** Make it with this skill: paint the frames
   and encode them to a full mp4, then send it with SendUserFile. For a narrated film, the video-studio pipeline
   still does the voice, captions, music and render; this skill makes the pictures (below).
3. **The user asks for this technique**, or for a picture built from light: space, skies, sunsets, glows, auras,
   gradients, nebulae, water, fog, abstract backgrounds, a reference image's look recreated in code.

It is **not** the first choice for type-heavy layouts and UI (reelkit), hand-made media like brush, collage or
chalk (animate-in-code), or real-world footage. Real 3D still means blender-3d, and only when the user wants it.

## The painting file
A Java class in the default package (no `package` line), named like its file, extending `Painting`:
```java
import imagewriter.*;
import static imagewriter.Paint.*;

public class Dawn extends Painting {
    private Lettering word;
    @Override protected void setup() {                                     // once: build the letters' distance field
        word = new Lettering("שחר", Lettering.font(option("font", null)), 0.5 * width, width / 2d, 0.3 * height, 60);
    }

    @Override public Color pixel(double x, double y, double t) {          // called for every pixel of every frame
        double v = y / height;                                              // 0 top … 1 bottom
        Color sky = Color.hex("#0B1026").lerp(Color.hex("#FF8A3D"), smoothstep(0.3, 0.9, v));
        double sun = coverage(circle(x, y, width / 2d, 0.8 * height - 40 * t, 60));   // soft-edged disc, rising
        Color c = sky.add(Color.hex("#FFE9B0").scale(sun)).add(Color.hex("#FF8A3D").scale(0.4 * Math.exp(
                -Math.hypot(x - width / 2d, y - 0.8 * height + 40 * t) / 140)));      // glow
        double d = word.distance(x, y), in = progress(t, 1, 0.5);           // the word: a distance like the sun
        c = c.add(Color.hex("#FF8A3D").scale(in * Math.exp(-Math.max(0, d) / 20)));  // its glow
        return c.lerp(Color.WHITE, in * coverage(d));                       // its fill, fading in
    }
}
```- Fields: `width height` (pixels), `seconds fps` (`seconds == 0` for a still), `frame`, `options` / `option(k, def)`.
- `Color` (0..255 doubles, may exceed 255 while adding light; clamped on write): `hex add scale tint lerp`.
- `Paint` (static): `clamp clamp01 mix sq smoothstep progress easeOut easeInOut`, shapes with soft edges
  `coverage(circle(…))`, `coverage(roundBox(…))`, randomness `hash noise fbm grain`.
- `Paint` also has `segment` (distance to a line segment: strokes, arrows, rays of light).
- `Lettering` (text as a distance): `Lettering.font(path)`, `new Lettering(text, font, width, cx, cy, reach)` or
  `Lettering.sized(text, font, other.size, cx, cy, reach)` to match another word's size; `distance(x, y)` and
  `distance(x, y, shiftX, shiftY, scale)` for motion; bounds `left top right bottom size`. `reach` = the widest glow
  or shadow in pixels. Hebrew and other right-to-left text comes out in the right order. Fonts: a project's Google
  Fonts (`node pipeline/cli.mjs fonts <p>` → `projects/<name>/fonts/`), passed with `--set font=<path>.ttf`.
- `Picture` (a file sampled per pixel): `new Picture(path)`, `picture.over(base, u, v, opacity)` with u, v the
  0..1 position inside the picture — you compute them from x, y (place, scale, rotate, warp it yourself).
- Build `Lettering`/`Picture` in `setup()`, never in `pixel()`. `pixel()` runs on several threads at once: keep it
  a pure function of (x, y, t) and read-only fields.
- The output is RGB, with no transparency: a painted image is a full rectangle (backgrounds, cards, whole pictures), not a cut-out.

Worked example: `examples/SixteenSunrises.java`, a sunrise from orbit over the night side of the Earth with city
lights, twinkling stars, a crescent moon, a sun that rises with growing rays, a glowing Hebrew title and a label
pill that fade in — every one of them a distance decided per pixel.

## How to decide every pixel (the method)
1. **Measure the reference** when there is one. Sample its colors (`python3 -I -c "from PIL import Image; …"` on
   a column every 50 px) and its layout as fractions of the frame (horizon at 47 %, title at 26 %…). Write the
   numbers down as constants; layout as fractions keeps any aspect ratio working.
2. **Split the frame into regions by a distance**: distance to a circle's edge (planets, suns, horizons), to a
   line (horizon, ground), to a box. The sign says which region the pixel is in, the size drives the fades.
3. **Each region is a gradient plus light**: a base gradient (keys from step 1, `lerp` between them), then glows
   added on top (`exp(-distance / size)`): light adds up, so sum the colors, don't overwrite them.
4. **Texture with noise**: `fbm` for clouds, terrain and paper; `hash` per grid cell for stars and sparkles. For
   depth, sample the noise in perspective (`distance = k / (pixelsBelowHorizon + c)`).
5. **Soft edges everywhere**: `coverage(signedDistance)` mixes the two sides across one pixel, so there are no jaggies.
6. **Finish**: a vignette (darker corners), a little `grain`, then text, labels and pictures — still inside
   `pixel()`: each is one more distance or sample, mixed in with `lerp` / `add` by its own coverage and opacity.
7. **Motion**: everything is a function of `t`: positions with `easeOut(progress(t, start, length))`, noise drift
   by moving its z with `t`, twinkles by `sin(t * speed + phase)`, fades by multiplying a coverage by `progress(t, …)`.
8. **Look, compare, adjust**: render a still or a `-grid.jpg`, Read it (side by side with the reference: paste
   both into one image with PIL), fix the numbers, repeat. Only then render the film.

## In the video studio
- **A shot**: a `clip` shot. Write `projects/<name>/shots/<ClassName>.java` (committed with the shots), take the
  shot's exact length and size from `node pipeline/cli.mjs shots <p>`, then
  `paint.sh projects/<name>/shots/<Class>.java projects/<name>/clips-src/<id>.mp4 --size <W>x<H> --fps <fps>
  --seconds <frames / fps> --set font=…`, then `clips <p>`. Leave out words the captions already carry.
  Look first with `…/frames/<id>-grid.jpg`.
- **An image element** (a background, a card, a scene): `paint.sh … projects/<name>/painted/<id>.png --aa 2`, then
  in `shots.json → images`: `{ "id": "<id>", "source": { "path": "projects/<name>/painted/<id>.png" },
  "license": "drawn in code (image-writer)", "credit": "", "page": "" }` and `elements <p>`. Paint it before
  `elements` runs. The PNG is ignored by git; the `.java` source is committed.
- **A whole film with no other engine**: every shot is a clip from a painting (one concept: shared palette and
  motion helpers, copy them between shot files); the pipeline still adds the voice, captions, music and SFX.
- **A video outside the studio** ("make me a 10 s clip of…", no narration): paint it to `output/<name>/<name>.mp4`,
  Read a `-grid.jpg` first, then send it with SendUserFile. To add music, mux a Freesound track with ffmpeg (Rule 3).

## Rules
- Free and local: no paid AI, no uploads. A painted image is original work (`license: "drawn in code (image-writer)"`,
  no credit needed); fonts come from Google Fonts, pictures drawn in with `drawImage` keep their own license.
- Never commit PNG/MP4 output. Commit the `.java` paintings.
- The kit (`kit/`) is shared: change a painting, not the kit, unless the kit really lacks something.
- Pixel-only, always (above). Never add a camera, scene, primitives, lights or a drawing call to a painting or
  to the kit, and never route around `check.sh`.
- Origin: `kit/ImageWriter.java` is the Mini-Pro ray tracer's ImageWriter (AvishayDev/Mini-Pro) — only the pixel
  writer; none of the ray tracer's camera, scene or geometry is used. Your formulas feed it directly.
